# 景点票务系统需求文档

概述：为各个旅游景点、文旅场馆等提供统一管理平台，进行自己运营的景点的票务管理、票务核验等。为用户提供预约、购票、票务核验功能。

当前阶段：第一阶段（MVP）

当前阶段目标：跑通最小完整业务

最后更新：2026-7-27

阶段历史：

## 系统角色及支持操作

- 游客：浏览场馆和场次、参观、下单预约、取消、查看票券。
- 运营者：维护场馆项目、发布场次、设置容量、查询订单和运营数据。负责具体场馆的日常经营管理，只能操作所属场馆。
- 工作人员：可以查询、扫描和核销电子票券，查看核销结果，权限小于运营人员，后面可以加点功能
- 系统管理员：管理系统上的各个项目，先简单实现就行

## 角色体验流程

- 游客：注册 -> 登录 -> 获取旅游景点列表 -> 获取景点详情页 -> 景点详情页各种场次+票展示 -> 票详情页信息展示 -> 点击购票后，订票页填写此张票对应的人员信息 -> 支付 -> 游客个人信息页展示 -> 预约时间前抵达景点 -> 票务核验入场

- 运营者：使用预置账号登录（由管理员创建） → 自己运营的景点展示 → 点进景点展示数据详情 -> 创建并发布票预约场次（日期、时段、容量、价格） → 查看某种票的数据详情

- 工作人员：登录账号（由运营者创建） -> 个人数据 -> 票核验功能

- 系统管理员：预制账号登录 -> 添加运营者账号

## 模块拆分

### 用户账号管理 `user`

概述：管理用户账户相关操作

### 用户认证 `auth`

概述：负责用户登录、注册、身份认证以及 JWT 令牌相关功能。

### 订单预约 `booking`

概述：负责游客提交预约订单、查询订单以及处理订单状态变化。

### 系统配置 `config`

概述：负责 Spring Boot、Swagger、跨域以及其他公共配置。

### 场次管理 `session`

概述：负责景点预约场次的创建、查询、修改和状态管理。

### 电子票券 `ticket`

概述：负责支付成功后的电子票券生成、查询和状态管理。

### 票种管理 `tickettype`

概述：负责景点票种及场次可售票种配置的管理。

### 景点管理 `venue`

概述：负责景点基本资料及景点运营账号、工作人员的管理。

### 核销管理 `verification`

概述：负责电子票券核销以及核销记录的保存和查询。

### 参观人管理 `visitor`

概述：负责游客常用参观人信息的新增、修改、查询和停用。

### Web 公共模块 `web`

概述：负责统一响应结果、全局异常处理和 Web 层公共组件。
