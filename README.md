# 景点票务系统需求文档

概述：为各个旅游景点、文旅场馆等提供统一管理平台，进行自己运营的景点的票务管理、票务核验等。为用户提供预约、购票、票务核验功能。

当前阶段：第一阶段（MVP）

当前阶段目标：跑通最小完整业务

最后更新：2026-7-27

阶段历史：

## 系统角色及支持操作

- 游客：浏览场馆和场次、参观、下单预约、取消、查看票券。
- 运营者：维护场馆项目、发布场次、设置容量、查询订单和运营数据。负责具体场馆的日常经营管理，只能操作所属场馆。
- 工作人员：可以查询、扫描和核销电子票券，查看核销结果，权限小于运营人员，后面可以加点功能
- 系统管理员：管理系统上的各个项目，先简单实现就行

## 角色体验流程

- 游客：注册 -> 登录 -> 获取旅游景点列表 -> 获取景点详情页 -> 景点详情页各种场次+票展示 -> 票详情页信息展示 -> 点击购票后，订票页填写此张票对应的人员信息 -> 支付 -> 游客个人信息页展示 -> 预约时间前抵达景点 -> 票务核验入场

- 运营者：使用预置账号登录（由管理员创建） → 自己运营的景点展示 → 点进景点展示数据详情 -> 创建并发布票预约场次（日期、时段、容量、价格） → 查看某种票的数据详情

- 工作人员：登录账号（由运营者创建） -> 个人数据 -> 票核验功能

- 系统管理员：预制账号登录 -> 添加运营者账号

## 模块拆分

### 用户与认证 Account

概述：注册登录

### 场地 Venue

概述：管理景点相关资料

### 场次 Session

概述：景点的下属，一个景点可以有多个场次，有日期、时间段、票种、容量等

### 实体票券 Ticket

概述：一种票绑定一次入场资格、绑定唯一参观人信息

### 票种 TicketType

概述：描述一类票券

### 参观人 Visitor

概述：一个真实人类身份，可用于绑定票券，实际入场人员

### 核销 Verification

概述：核销票务相关

### 订单 Order

概述：订单管理、退款、付款、取消等
