# 个人项目日记

记录项目思考的每一个点

## 2026/7/27

- [项目设计] 角色思考：需要核销工作人员，可以把票务核销的功能下派给多人/机器，而不是堆在运营人员上。同时保证其中一个账号异常时其他的账号仍然可以核销票务。

- [项目设计] 景点运营者直接使用预制账号登录，由系统管理者注册

- [项目设计] 怎么拆分模块？按照对象（用户、景点、场次、票、参观人、订单等） + 特定行为（登录、核销等）来拆

- [技术栈选型] flyaway控制数据库版本

- [表结构设计] 一开始设计了“场次”这个概念，一个场次下可以发布多种票券。后来觉得多余，毕竟票券上可以附带时间段信息，这样直接venue->ticket不是很简洁吗？但是后来还是保留了，因为“场次”可以保留该时间段各种票券的总体性的信息，比如场馆剩余容量等，可以控制客流+动态调整票量
