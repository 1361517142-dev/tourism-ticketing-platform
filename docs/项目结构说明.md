# 项目结构说明

本项目采用 Maven 多模块的模块化单体结构，并在应用模块内部按业务域组织代码。

```text
tourism-ticketing-platform/
├── tourism-common/   跨模块通用响应、异常、常量和纯工具
├── tourism-pojo/     Entity、DTO、VO、枚举
└── tourism-server/   Spring Boot 应用与业务实现
```

## tourism-common

```text
com.qinghuan.common
├── response/         统一接口响应
├── exception/        通用错误码和业务异常
├── constant/         真正跨业务域的稳定常量
└── util/             无状态、无业务语义的工具
```

`tourism-common` 不依赖 Spring Web，也不放具体业务逻辑，保证其他模块可以低成本复用。

## tourism-pojo

```text
com.qinghuan.pojo
├── entity/           与数据库表对应，仅在数据访问和服务内部使用
├── dto/              API 请求、服务命令和查询条件
├── vo/               API 返回视图
└── enums/            数据库状态和业务枚举
```

- Entity 不直接暴露给接口调用方。
- DTO 和 VO 后续按业务域建立子包，例如 `dto.booking`、`vo.venue`。
- 数据库状态枚举名称与 Flyway 脚本中的字符串值保持一致。
- 金额使用 `BigDecimal`，日期时间使用 `java.time` 类型。

## tourism-server

```text
com.qinghuan
├── auth/             注册、登录和认证
├── venue/            景点管理
├── session/          场次与容量
├── tickettype/       票种和场次售价
├── visitor/          参观人
├── booking/          订单、支付、取消和退款
├── ticket/           电子票
├── verification/     核销
├── config/           跨域基础设施配置
└── web/              统一异常处理等 HTTP 基础设施
```

每个业务域按需要创建：

```text
<domain>/
├── controller/       参数校验、HTTP 协议转换、调用 Service
├── service/          业务流程和事务边界
└── mapper/           MyBatis 数据访问
```

不要为了目录完整创建空的 Controller、Service 或 Mapper。业务域之间通过 Service 协作，禁止直接调用其他业务域的 Mapper。

MyBatis XML 文件统一放在：

```text
tourism-server/src/main/resources/mapper/<domain>/
```

任何数据库结构变更都通过新的 Flyway 迁移完成，已经执行过的版本化迁移不得修改或删除。
