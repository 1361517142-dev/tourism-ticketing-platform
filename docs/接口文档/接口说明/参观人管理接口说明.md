# 参观人管理接口说明

对应的 OpenAPI 文件：[visitor-openapi.json](../接口json/visitor-openapi.json)

参观人由游客账号维护，用于下单时选择实际入园人。当前 MVP 只提供单个参观人的基础查询、新建、修改和状态管理，不提供批量操作与物理删除。

## 通用业务规则

- 所有接口均要求游客登录，请求头携带 JWT。
- `userId` 从当前登录信息中获取，前端不传递。
- 游客只能访问和修改自己名下的参观人。
- 同一游客下，证件类型与证件号码的组合不能重复。
- 接口返回的证件号码必须脱敏，不返回证件号码明文。
- 证件类型和证件号码创建后不通过修改接口变更；如果录入错误，应停用旧参观人并重新创建。
- 停用参观人不会影响历史订单，但该参观人不能再用于创建新订单。

## 1. 查询参观人列表

```http
GET /tourist/visitors?status=ACTIVE
```

查询当前游客名下的参观人。`status` 为可选参数，可传 `ACTIVE` 或 `DISABLED`；不传时返回全部状态。

个人账号通常只维护少量参观人，因此 MVP 阶段不分页。

## 2. 新建参观人

```http
POST /tourist/visitors
Content-Type: application/json
```

请求示例：

```json
{
  "name": "张三",
  "idType": "ID_CARD",
  "idNumber": "440101199001011234",
  "phone": "13800138000"
}
```

业务规则：

- 姓名、证件类型、证件号码必填，手机号选填。
- 新建后的状态默认为 `ACTIVE`。
- 若当前游客已存在相同证件类型和证件号码的记录，返回冲突错误。
- 创建成功后返回新参观人的 ID。

## 3. 获取参观人详情

```http
GET /tourist/visitors/{visitorId}
```

返回当前游客名下指定参观人的基本信息。证件号码以脱敏形式返回，例如 `440***********1234`。

参观人不存在或不属于当前游客时，统一按资源不存在处理。

## 4. 修改参观人信息

```http
PUT /tourist/visitors/{visitorId}
Content-Type: application/json
```

请求示例：

```json
{
  "name": "张三",
  "phone": "13900139000"
}
```

业务规则：

- MVP 阶段只允许修改姓名和手机号。
- 证件类型与证件号码不在该接口中修改。
- 参观人必须属于当前游客。

## 5. 修改参观人状态

```http
PATCH /tourist/visitors/{visitorId}/status
Content-Type: application/json
```

请求示例：

```json
{
  "status": "DISABLED"
}
```

业务规则：

- 状态只允许为 `ACTIVE` 或 `DISABLED`。
- `DISABLED` 表示停用，停用后不能用于新订单。
- 状态可以重新改为 `ACTIVE`。

## MVP 暂不提供的接口

- 不提供物理删除接口，以免破坏参观人与历史订单之间的关联。
- 不提供批量新建、批量修改或批量停用接口。
- 不提供复杂的实名核验或外部证件认证能力。
